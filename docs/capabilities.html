02 / CAPABILITIES

不是会写文案，是每一句都有出处。

ShopMind 先建立证据，再谈表达。模型只允许在证据白名单内写作，校验不通过的内容不会进入导出包。

Not Just a Chat Model

为什么不是
「纯大模型」？

大模型负责表达，ShopMind 负责它能不能说、该说什么、说完有没有出处。四件事把「生成」变成「可交付」。

01 / EVIDENCE FIRST

证据先行

先扫描来源、抽取证据，再让模型在证据白名单内写作。没有依据的卖点不会被当成事实，也不会被写成「用户都说好」。

02 / STRUCTURE FIRST

结构先行

商品理解、经营判断与创意方向都是结构化数据，字段可审阅、可修正；不是一段不可控的长文本，而是一条能回滚的流水线。

03 / VALIDATION LAST

校验兜底

禁用词、越界证据、越界素材、待确认证据都会触发 PASS / WARN / FAIL。FAIL 不是提示，而是阻断导出。

04 / OFFLINE READY

离线可用

未配置 Key 时走规则与模板，五步仍可完整走通。断网、换机器或现场网络不稳定，都不影响演示主流程。

Six Channels

六个渠道，
不是六份复制。

同一方向、同一组证据，按平台重写语气与结构。六个渠道共享事实，不共享模板。

语气 · 视觉化、可拍摄

Validation Codes

把「感觉不对」，
变成可阻断的条件。

校验不是给文案打分，而是守住品牌与事实的边界。每一条结论都对应一个可解释的 code。

content_generator.py / validate_content_item PASS · WARN · FAIL
Code Level 触发条件 处理方式
forbidden_word FAIL 命中品牌禁用词。 阻断该条内容，修正后重新生成。
evidence_outside_direction FAIL 引用了当前方向白名单之外的证据。 阻断，回到方向页重新绑定证据。
asset_outside_direction FAIL 引用了白名单之外的图片或视频素材。 阻断，替换为方向推荐素材。
pending_evidence WARN 部分依据仍为待确认状态。 保留内容并标注，提示人工复核。
open_questions WARN 方向仍有未补齐的资料缺口。 在正文中显式标注「资料不足」。
checks_passed PASS 未发现客观阻断问题。 可进入导出；仍需人工审阅。
NOTE stale 证据不参与表达，并会在导出阶段阻断整包。 宁可停下来补一条证据，也不让一句没有出处的话进入内容包。

Brand Memory · C1

品牌记忆：
只读接入，不越界。

品牌规则可以统一语气与表达边界，但不能冒充商品事实或证据。C1 只把它放进商品理解与内容生成两个模型请求。

工作区 brand_memory.json 只读快照 · 超过 2000 字符截断 · 不写入系统提示词
服务端开关（默认关闭）
商品理解请求 统一语气 / 取舍表达 / 避免重复
内容生成请求 遵守品牌语气与表达边界
可追溯标记：brand_memory_applied / brand_memory_updated_at。未启用时明确显示「未生效」，不谎称使用。
C1 已接入 C2 未做

品牌规则明确不进入以下环节：

  • 经营判断：不改变本地规则与判断结论。
  • 创意方向：不参与方向生成或白名单。
  • 离线模板：不修改规则与模板正文。
  • 图片 / 视频提示词：不改变媒体生成内容。
边界来自实现约束，不是能力宣传：C1 只覆盖两个模型请求；开关关闭时，请求与改动前保持一致。

Boundaries

能力边界，
写在产品里。

明确不做什么，和明确能做什么同样重要。以下声明同时出现在界面、导出包与页脚。

仅基于本地资料

所有内容来自你提供的商品资料、评价与图片，不做外部市场推断，也不编造用户反馈。

未接入市场 / 利润 / 竞品

因此不对市场规模、利润空间与实时竞品作任何判断；相关结论需要你另行补充数据。

演示数据为虚构

仓库内品牌、商品参数与评价均为比赛演示数据，不代表真实用户反馈或真实经营表现。

生成内容仍需人工审阅后发布。ShopMind 不替代品牌决策，也不承诺投放效果；它做的是把资料整理成可检查、可修改、可交付的创意初稿。
