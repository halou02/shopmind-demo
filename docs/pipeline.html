03 / PIPELINE

五步，每一步都留下文件。

录入 → 理解 → 方向 → 生成 → 导出。每步都有明确输入、结构化输出与固定产物文件名，任一步骤失败即停，不会带着错误结果继续往下跑。

Fail fast Structured output 7 artifacts

STEPS / 01—05

01 录入ingest 02 理解understand 03 方向direction 04 生成generate 05 导出export
01

录入

scan_sources · app/steps/scan_sources.py

输入

  • 商品信息表（xlsx / csv 多 Sheet）
  • 用户评价、历史文案（txt / md）
  • 商品图片与短视频素材（png / jpg / webp / mp4）
  • 品牌规则与拍摄清单

主要输出

  • 来源索引：按扩展名与文件名语义分类
  • 每个来源的文件哈希与解析状态
  • 素材资产表：角色（主图 / 场景 / 细节）与路径
source_index.json

失败即停：来源不可读或目录缺失时写入索引失败，用 index_write_failed 中止，不产生后续产物。

02

理解

extract_evidence · understand_product · judge_business

输入

  • 来源索引与解析出的文本片段
  • 商品图片（视觉能力开启时参与理解）
  • 工作区品牌规则（仅启用时作为只读上下文）

主要输出

  • 证据集：ID、原文、来源定位与状态
  • 商品理解卡：参数、卖点、人群、待验证项
  • 经营判断：机会、风险、开放问题与下一步
evidence.json product_understanding.json business_judgment.json

失败即停：抽取或写入失败时用 evidence_write_failed / understanding_write_failed 中止；理解卡可在界面上手动修正后重跑。

03

方向

generate_directions · app/steps/generate_directions.py

输入

  • 商品理解卡与经营判断
  • 证据白名单（可用证据 ID）
  • 素材资产表（可用图片与视频）

主要输出

  • 多个创意方向：人群、洞察、核心表达
  • 每个方向的 evidence_ids 与 asset_ids 绑定
  • 每个方向的禁忌表达与待验证项
creative_directions.json

失败即停：方向写入失败用 directions_write_failed 中止；方向白名单为空时不进入生成阶段。

04

生成

generate_content · app/steps/generate_content.py

输入

  • 选定的创意方向（必须先选定）
  • 商品理解、证据集与素材路径
  • 工作区品牌规则（仅启用时作为只读上下文）

主要输出

  • 六个渠道的内容条目，逐条标注校验等级
  • 每条内容的 evidence_ids 与 asset_ids 引用
  • 生成来源、失败数与警告数汇总
content_package.json content/*.md

失败即停：任一渠道校验为 FAIL 即计入 fail_count，步骤状态置为失败；写入失败用 content_write_failed 中止。

05

导出

export_content_package · app/export/content_package.py

输入

  • 商品理解、经营判断、创意方向与证据集
  • 内容生成报告（六渠道条目）
  • 来源索引与输出目录（必须与素材包隔离）

主要输出

  • 标准内容包目录：结构化 JSON + 六渠道 Markdown
  • 清单与逐文件 SHA256 校验
  • 导出状态（ready / partial / blocked）与原因
manifest.json README.md source_index.json

失败即停：导出目录位于素材包内、存在 stale 证据或内容 FAIL 时，标记为 blocked 并清理暂存目录；校验不一致则不落盘。

Fixed Artifacts

固定产物，
文件名就是接口。

不依赖界面就能审阅：产物文件名固定，字段结构稳定，可以直接接进你自己的工具链或人工复核流程。

STEP 01 source_index.json

来源索引：文件类型、语义分类、哈希与解析状态。

STEP 02 evidence.json

证据集：ID、原文、来源定位与 confirmed / pending / conflict / stale 状态。

STEP 02 product_understanding.json

商品理解卡：参数、卖点、人群与待验证项。

STEP 02 business_judgment.json

经营判断：机会、风险、开放问题与下一步动作。

STEP 03 creative_directions.json

创意方向：人群、洞察、核心表达与证据 / 素材绑定。

STEP 04 content_package.json

六渠道内容条目与逐条校验结果。

STEP 05 manifest.json

包清单：文件列表、SHA256、证据计数与导出状态。

STEP 04—05 content/*.md

六个渠道的可读正文，带品牌与边界声明。

Fail Fast

宁可停下，
不带着错误往下跑。

如果某一步的产物不合格，后面所有漂亮的文案都只是建立在错误前提上。

因此每一步都写入独立产物、独立校验：上游不通过，下游不会自动「脑补」补齐。

产物可回滚

每步输出独立文件，修正上游后重跑即可，不需要从头重来。

状态可读

complete / partial / failed / blocked 明确写入步骤结果，界面直接展示。

目录可审计

SHA256 校验逐文件比对，任何改动都会被发现。
